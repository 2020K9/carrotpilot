## K9 停车方式选择（试验） (`K9StopMode`)

选项：0 基本制动 / 1 v12原版 / 2 v12k9 / 3 v13原版 / 4 C1 / 5 C1+（2026-10-25整理：删除原1 v10、原2 v10+轻度抖动修正、原3 v11及其代码；2026-10-26新增3 v13原版；2026-10-27新增4 C1、5 C1+）

单选（不叠加）。仅限起亚K9非CAN-FD摄像头SCC openpilot纵向，其他车辆始终等同0。0：基本制动（默认）。

1：v12原版——同一页面（https://leegrt.org/oppo/creep_fix/changelog.html）的creep_fix v12（旧CAN纵向整合补丁v12，为Niro EV编写）的两段代码一行不改直接放在菜单1条件下（指示：原版不改直接上传）。未针对K9做任何调整。K9闭环模拟（20次停车×72条件，对比原v11）：停车距离中位+0.26m（最大+2.66m），前车最小间距最小-2.39m，3秒内未停住103→510次，即在K9上停得更晚更远；停车末端冲击更小（末端jerk中位22→6）。页面的改进说明是Niro EV记录，不是K9结果。

2：v12k9——按v11时的方式针对K9调整的v12。停车阶段与低速pid蠕行补偿同原3（v11）；从v12只采用1.0m/s以下pid指令双向变化限制（前车3m以内不限制加大制动，放松限制仅在0.52m/s以上；10/25修正：加大制动限制只在原v11防再踩区间（0.95m/s以下、已减速超过0.18m/s²），同样输入下不比v11晚踩；放松限制只在车没有比计划更强减速时（eff_ac ≥ aTarget-0.02））和jerk（1.15m/s以下上限0.7~1.6、下限1.0~1.3）。ComfortBand（10/25晚修正）：原页面为0，但K9实车上带宽0的停车在7km/h以下出现6~7Hz抖动（发送带宽的0号停车没有），因此2.5m/s（9km/h）以下发送与0相同的原始带宽，到3.0m/s线性降为0，以上仍为0，StopReq锁定后在0.4秒内降回0。10/26补充：48次记录停车中有带宽时实际制动比请求弱（每单位带宽+0.146±0.054m/s²），所以发送带宽期间减速请求加强0.20m/s²（乘以发送带宽比例，在加速度0~-0.3之间渐入，加速时不加），3.0m/s以上和带宽0时不变；带宽停车中0.3m/s以下0.15秒内减速弱于-0.10m/s²（停住不动）时立即发StopReq。jerk不变（日志估计、模拟）。未采用v12停车阶段修改（模拟中停车距离p90+0.20m、间距最小-0.45m）。模拟对比原v11（10/25修正后）：停车距离最大+0.003m，间距最小-0.004m（噪声范围内），3.25→1.6km/h放松后再抓1641→1548次，比v9弱的帧43370→39946。

3：v13原版——页面（https://leegrt.org/oppo/creep_fix/）的creep_fix v13（“310--3黄金包络·急刹保护·无冲击停车完成版”）两段代码一行不改直接放在菜单3条件下（2026-10-26指示：v13出来了，保留v12，新增v13；1 v12原版保持不变）。按代码与v12原版的区别：四轮均低于0.03m/s持续28帧（0.28秒）也算真实停止；StopReq前目标-0.28~-0.44m/s²，减速不足基准-0.03~-0.18，补强最大-0.08；0.28m/s以下未停住蠕行超过120帧（1.2秒）则每帧多踩0.002、最多0.22（蠕行保护）；StopReq后保持25帧（0.25秒）再以0.0018/帧降到-0.50；1.5m/s以下pid过度制动最多65%向计划混合，蠕行补偿-0.24~0，0.95m/s以下已在减速时不比按速度的-0.29~-0.64m/s²踩得更重；1.0m/s以下双向变化限制；jerk：1.15m/s以上按减速请求给下限加0~4.0（decel_boost），1.15m/s以下上限0.7~1.8、下限1.0~1.2，所有速度ComfortBand 0。未针对K9做任何调整。页面的改进说明是Niro EV记录，不是K9结果。

4：C1——只改2（v12k9）停车末段的版本（2026-10-27指示“c1.c1+ 3번 4번추가해”/“그럼 4.5에넣어야지”：3 v13原版不动，C1、C1+放在4、5；菜单2代码不变，另行加入）：末段积分1.5→0.5，与延迟0.35秒的目标比较，即将停住时（速度<0.5秒×减速）不再加踩，末段从上一次请求无缝开始，车仍在滚动时不因出发计划发StopReq（2在0.15m/s以下会发）。闭环模拟（9000次）中冲击、抖动少于2，但6个前车条件的最近间距短于1 v12原版（前车1.0m条件1.57m，原版1.64m）。

5：C1+——C1加上前车距离中断过滤（远处雷达前车之后紧接“前车可见+距离0.0”时，用该远距离减去本车行驶距离；2026-10-27 05:15停车）、末段转入保持请求时不出现台阶（12m内有前车时不做）、有前车时末段目标为前车后4.0m并在预计停在4.0m以内时加踩。闭环模拟（9000次）中冲击、抖动少于2，前车1.0m条件间距2.11m，但前车3.0m+延迟条件3.717m，比1 v12原版（3.724m）短7mm。前车距离中断后前车消失时，2在滚动中就发StopReq，C1+到即将停住前不发。4、5仅为模拟与记录回放结果。

共同强制动放松抑制（0~5全部，2026-10-24晚）：3.0m/s以上pid中因前车接近使减速请求≤-1.0m/s²后、直到高于-0.5为止，仅在规划器缓慢放松（规划jerk 0~1.0m/s³）时把SCC14 JerkUpperLimit保持在下限0.5（日志估计）。其他值（6以上、负数）按0处理。约0.5秒内生效并重新开始。保存值在更新后首次启动时迁移一次（K9StopModeVer 3）：原1·2·3→2（v12k9），0不变，其他值保持。3 v13原版、4 C1、5 C1+也需手动选择（标记保持3）。2026-10-26~27画面最大为3，保存的4、5只可能是手写的值：以前按0处理，此更新后4 = C1、5 = C1+（不迁移保存值）。1~5尚未经实车确认。

## 车道辅助 (`K9LaneAssist`)

选项：0 关闭（现有） / 1 开启（全部车道辅助）

0 关闭：保持原样。1 开启：减少车道线抖动 · 无车道线模式保持车道中央（1km/h起）· 只见一侧车道线时保持间距 · 车道模式切换平顺。力度 = 中央修正强度，左右位置 = 车道偏移左右修正（`PathOffset`）。详细说明见 `docs/dev/k9_lane_assist.md`。

## 中央修正强度 (`K9LaneCenterGain`)

0~200%，10%步进，默认100

拉回车道中央的力度。100 默认 / 0 不拉 / 200 两倍。仅无车道线模式。行驶中立即生效。

## 车道偏移左右修正 (`PathOffset`)

−150~+150cm，默认0（菜单位置自2026-10-25移到车道辅助下方）

让车在车道内左右移动（cm）。− 左 / + 右。车道模式始终适用；无车道线模式仅在车道辅助为1时适用，最多±30cm。行驶中立即生效。

## 外部 HUD 画面选择（试验） (`K9ExtHud`)

选项：-1 不使用（现有） / 0 现有外部 HUD 画面 / 1 出租车计价器画面（2026-10-24 前的选项名）

单选。-1：不使用（默认），与以前相同，由“外部 HUD 显示”(ClusterHud) 和外部 HUD 设置决定。0：现有外部 HUD 画面，与 ClusterHud=1 的画面相同，外部 HUD 各项设置照常生效。1：出租车计价器画面。左侧驾驶画面与 0 相同，右侧信息面板显示计价器（保诺模范出租车计费：起步 7,000 韩元/3 公里，每 144 米 200 韩元，每 35 秒 200 韩元，距离·时间并算（14.8 km/h 以下计时），夜间 23~04 点加收 20%），画面为 C1 样式，保诺的贝壳随方向盘角度(steeringAngleDeg) 1:1 转动，此画面不绘制胡萝卜方向盘图标。按实际距离和时间计费：不再与副驾驶乘客检测联动（2026-10-24）。计价器从单独的空车画面开始，只由遥控 App 的 4 个按钮操作：开始（清零后立即计费）、暂停/继续、结算（单独的结算画面）、空车（任何状态下回到空车画面并清零）。仅供显示。改为 0 再改回 1 即重置计价器（费用、距离、时间归零，从起步价开始）。防冲突：选 0 或 1 时 ClusterHud 自动关闭(0)；打开 ClusterHud(1) 时本项恢复为 -1。只运行一个 HUD 程序。0↔1 切换无需重启 HUD，约 1 秒内生效。未经实车验证。

## 出租车计价器季节背景（试验） (`K9MeterSeason`)

选项：0 自动（按月份） / 1 春 / 2 夏 / 3 秋 / 4 冬（2026-10-24 前的选项名）

仅在“外部 HUD 画面选择”为 1（出租车计价器画面）时使用的附加选项，选择计价器背景的季节。0：自动（默认），随月份变化（3~5月春，6~8月夏，9~11月秋，12~2月冬）。1：春。2：夏。3：秋。4：冬。白天(05点)·黄昏(16点)·夜晚(19点)切换在任何值下都按时间照常进行。其他值（超出范围）按 0 处理。HUD 只读取此值，约 1 秒内生效。与计费无关。未经实车验证。
