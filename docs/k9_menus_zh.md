## K9 停车方式选择（试验） (`K9StopMode`)

选项：0 基本制动 / 1 v10 / 2 v9+抖动修正 / 3 v10+带宽0.2 / 4 v10+抖动修正（2026-10-24 前的选项名）；5 v10+轻度抖动修正（2026-10-24 新增）；6 v11（2026-10-24 新增）

单选（不叠加）。仅限起亚K9非CAN-FD摄像头SCC openpilot纵向，其他车辆始终等同0。0：基本制动（默认）。1：v10——忠实移植同一页面的creep_fix v10（旧CAN纵向整合补丁v10）。结构与v9（同一页面creep_fix v9的独立实现：为Niro EV发布的creep_fix v9（https://leegrt.org/oppo/creep_fix/）的独立实现：停车状态下在真正停止、计划减速≤-1.0m/s²、减速不足、aEgo>0.06或前车3m以内之前不发送StopReq并逐渐调整减速请求，之后发送StopReq与至少-0.50m/s²；ComfortBand设为0。会改变StopReq时机、停车距离与手感。）相同，但停车羽化目标在0.05~0.42m/s为-0.26~-0.52m/s²（车轮停止前0.25m/s以下制动更轻，弱于v9），min_decel与释放速度条件（0.12m/s）按页面，StopReq锁定后减速请求每帧0.0035（0.35m/s³）逐渐压到-0.50m/s²（计划减速≤-1.0m/s²时立即）。前车3m锁定及解除/接管时恢复原指令与v9相同。部分区间制动弱于v9，尚未经实车确认。2：v9+抖动修正——StopReq时机与安全锁定与v9相同，但前车锁定改为2.5m以内（而非3m）：K9停在前车后2.2~3.0m，3m锁定会在车辆仍在移动时发送StopReq导致顿挫（2026-10-22 17:06行驶日志）；前车2.5~3.0m时不发送StopReq，保持v9的锁定减速（至少-0.50m/s²）且不松开；2.0m/s以下把ComfortBand恢复为原值（2.0~3.0m/s混合，0.5秒内变化），并补偿减速请求，使其不会比v9制动更弱（3.0m/s以下减速时最多多制动0.10m/s²，在0.6~0.3m/s之间减为0；低于0.8m/s时向基本制动值混合一半，仅在制动更强时）。依据2026-10-22 K9日志。另外（将creep_fix评估方法用于K9日志）：6.4km/h以下2附加的制动不会先松后踩；vEgo 0.15m/s以下（K9车轮已停）不再松开；羽化不松到-0.48m/s²以上，以免发动机蠕行拖长停车；StopReq锁定时也不松开。仅经日志重放与仿真确认。3：v10+带宽0.2——减速请求、StopReq、精细分段制动、0.35m/s³锁定斜坡与前车3m锁定每帧与1（v10）逐位相同；只在1把ComfortBand（ESC可偏离请求值的幅度）发为0的帧，把上下ComfortBand发为0.20m/s²（CAN 0.02单位，正好0.20）。数值变化时每步最多0.04，不会突变。2026-10-23日志中停车前5~9Hz抖动：带宽0的1为0.145/0.094，带宽0.76~0.80的2为0.027/0.013m/s²。没有发送0.20带宽的K9日志，抖动减少多少只是估计。仅经日志重放与仿真确认。4：v10+抖动修正——减速请求、StopReq、精细分段制动、0.35m/s³锁定斜坡与前车3m锁定每帧与1（v10）逐位相同；在1把ComfortBand（ESC可偏离请求值的幅度）发为0的帧，2.0m/s（约7km/h）以下把上下ComfortBand发为原值（0基本制动所发的值，停车前约0.8/0.7m/s²），3.0m/s以上与3相同发0.20m/s²，之间混合。数值变化时每步最多0.04，不会突变。2026-10-22/23 K9日志20次停车中，2.0m/s以下5~9Hz抖动（上下晃动）带宽0时为0.07~0.12，原带宽时为0.02~0.04m/s²；2.0m/s以上无差别。日志无法判断带宽是否改变实际减速，因此减速请求与1相同（不会变弱）。抖动减少为日志估计；仅经日志重放与仿真确认。其他值（5以上、负数）按0处理。踏板、接管、解除控制或CAN异常时立即恢复原指令。约0.5秒内生效并重新开始。2026-10-23菜单变更：删除单独的v9项，编号前移一位（之前1d0961da为1 v9、2 v10、3 v9+抖动修正）；保存值不迁移：保存值1现为v10，2为v9+抖动修正，3为v10+带宽0.2（4为2026-10-24新增）。不沿用旧0~6菜单的保存值，从0开始。1、2、3、4尚未经实车确认。基于EV数值，在K9上的效果、舒适性与安全未经验证。

2026-10-24 新增 5：v10+轻度抖动修正——减速请求、StopReq、精细分段制动、0.35m/s³锁定斜坡、前车3m锁定与加加速度上限每帧与1（v10）逐位相同；在1把ComfortBand（ESC可偏离请求值的幅度）发为0的帧，2.5m/s（9km/h）以下把上下ComfortBand发为0.60/0.50m/s²，3.0m/s（约11km/h）以上与1相同发0，之间逐渐减小。数值正好落在CAN 0.02单位上，每步最多0.04，不会突变。同样20次停车日志中，2m/s以下带宽0.5~0.7时的抖动（0.024~0.033m/s²）与0.7~0.9时（0.025~0.037）相同，2.5m/s以上开启带宽也不减少抖动。因此用比4小的带宽争取与4相同的抖动减少（估计）。若带宽会改变实际减速，停车位置比4更接近1（闭环仿真：相对1停车距离中位数-0.18/+0.10m，4为-0.26/+0.13m）。抖动减少为日志估计；仅经日志重放与仿真确认。加入5后，其他值为6以上、负数按0处理。1、2、3、4、5尚未经实车确认。

2026-10-24 新增 6：v11——把同一页面的creep_fix v11（旧CAN纵向整合补丁v11，为Niro EV编写）移植到1（v10）之上。按页面代码原样采用：真正停止（TCS13 StandStill、速度低于0.05m/s）须连续12帧（0.12秒）才发StopReq（计划减速≤-1.0m/s²、减速不足、aEgo>0.06、前车3m以内仍立即锁定）；停车前减速目标下限-0.26→-0.28m/s²，减速不足线-0.02→-0.04；晚进入停车状态且请求弱于目标时每帧多踩0.005；0.12m/s以下释放步长0.0030（原0.0032）；StopReq后压向-0.50m/s²的速度为每帧0.0025（0.25m/s³，v10为0.0035）。0.95m/s以下已比-0.18m/s²减速更强时不再加深请求（计划减速≤-0.80m/s²或前车3m以内时不用）。加加速度上限只在0.65m/s以下提高（0.05m/s 0.7，0.14~0.45m/s 1.8，0.65m/s 0.8）。ComfortBand与1相同为0。K9未采用：页面在1.5m/s以下减小蠕行补偿（-0.26至0）和PID过度制动混合（最多55%），是为Niro EV再生→液压切换设计，且都偏少制动；K9闭环仿真（20次停车×72条件）中相对1停车距离中位数+0.08m（最大+0.40m），前车最小间距中位数-0.08m（最小-0.49m），因此低速pid减速保持与1（v10）相同（此时距离中位数0，间距最小-0.01m）。前车3m锁定及解除、接管、踏板、CAN异常时恢复原指令与1相同。页面的改善说法来自Niro EV日志，不是K9结果。仅经日志重放与仿真确认。加入6后，其他值为7以上、负数按0处理。1~6尚未经实车确认。

## K9 车道模式偏移修正选择（试验） (`K9LaneFix`)

选项：0 关闭（现有） / 1 F1（2026-10-24 前的选项名）

单选。仅改变车道模式（沿车道线路径行驶时）。0：关闭（默认），与以前相同。1（F1）：①车道模式路径从车辆当前位置（模型路径起点）开始，在2秒内平滑并入车道线路径；初始偏差大时并入时间最多延长到4秒，但只在并入曲率保持较小的范围内延长，高速时仍为2秒。车道模式刚开启时，该修正在0.5秒内逐渐加入。②车道模式关闭、回到模型路径的瞬间起，转向指令变化限制在横向加加速度2.5m/s³以内（低于现有安全限制5m/s³），正常变化进入该范围即解除，最长2秒。变道中或转向关闭时不使用。曲率/加加速度/加速度安全限制、无车道线路径、车道模式开关条件和停车功能不变。更改立即生效（0.05秒内）并重置过渡状态。仅通过日志回放与仿真确认，未经实车验证。

## K9 车道线后处理选择（试验） (`K9LRView`)

选项：0 关闭（现有） / 1 开启（车道线跟踪）（2026-10-24 前的选项名）

单选。0：关闭（默认），与以前相同（直接使用模型输出）。1：开启。modeld按模型给出的标准差对四条车道线逐点做卡尔曼平滑；每帧更新前先按本帧模型输出的本车速度和横摆角速度移动上一帧车道线（自车运动预测），减少入弯和车道弯曲时的滞后。近处点平滑更多，远处点、横摆角速度大或与模型值差异大时平滑更少；车道线概率约0.15秒平均。某条车道线一帧内跳动超过1米（变道等）时立即恢复为模型原值。车道高度、道路边缘、模型路径和转向/速度安全限制不变。无额外GPU计算，CPU占用可忽略。录像回放验证中车道线闪烁比原值减少约61%；代价是入弯时约晚1.3帧（约0.06秒），概率变化约晚0.1~0.15秒反映，压线变道时可能约晚0.03秒跟随（遗留问题）。5秒内生效，关闭再开启会重新开始。仅通过低画质录像回放仿真和设备日志回放确认，未经实车验证。

## 单侧车道线间距保持（试验） (`K9OneLaneHold`)

选项：0 关闭（现有） / 1 开启（单侧车道线间距保持）（2026-10-24 前的选项名）

单选。0：关闭（默认），与以前相同。1：开启。仅在无车道线模式（跟随模型路径）下工作。两侧车道线都清晰时，分别测量车左缘↔左车道线、车右缘↔右车道线的间距（K9车宽1.915米，滤波），记住以车道中心为准的目标间距（车道宽/2 − 车宽/2）和最小间距（两者较小值，至少0.3米）。之后只看到一侧车道线时，加一点转向曲率使与该线的间距回到记住的中心间距；比最小间距更近时推得更强。两侧都看到或都看不到时不加任何量（照旧无车道线）。变道、转向灯、驾驶员转向、转弯（曲率大）、低速（低于29km/h）、车道宽突变或前方宽度变化（汇入、分岔）、可见车道线跳动/抖动/与模型路径分开时，1秒内恢复原样。15秒或300米内未再看到两侧车道线则丢弃记忆；可见车道线与记忆间距相差超过0.5米，或已全力修正仍持续远离超过1秒（车道变宽、汇入、分岔）时立即丢弃并恢复原样。此外，若可见车道线自己移动（无法由车辆自身运动解释：上一帧车道线沿模型路径推算），约1.5秒累计超过0.12米（汇入、分岔线）则立即丢弃记忆，并立即把修正目标降为0（输出按加加速度上限减小）；该移动超过0.03米时已开始减小修正量；只剩一侧车道线后的前0.6秒不修正，只观察（车道线中断0.3秒以内不重新等待）。模型路径本身快速转向时（横向加加速度超过0.1~0.3m/s³）不再向同一方向追加（被检测切断的修正量照常减小）。阻尼（车道线位置变化率）只收回本功能自身附加的横向速度，车道线估计抖动时也不会向中心目标反方向推。附加量横向加速度不超过0.25m/s²（最小间距内0.6），变化不超过0.15m/s³，开关各有1秒过渡；退出过渡期间修正量只减不增、方向不变。可见车道线概率低于0.9时按比例减弱（0.45时为0）。车道模式下不工作。仅通过设备日志回放和闭环仿真确认，未经实车验证。

## 外部 HUD 画面选择（试验） (`K9ExtHud`)

选项：-1 不使用（现有） / 0 现有外部 HUD 画面 / 1 出租车计价器画面（2026-10-24 前的选项名）

单选。-1：不使用（默认），与以前相同，由“外部 HUD 显示”(ClusterHud) 和外部 HUD 设置决定。0：现有外部 HUD 画面，与 ClusterHud=1 的画面相同，外部 HUD 各项设置照常生效。1：出租车计价器画面。左侧驾驶画面与 0 相同，右侧信息面板显示计价器（保诺模范出租车计费：起步 7,000 韩元/3 公里，每 144 米 200 韩元，每 35 秒 200 韩元，距离·时间并算（14.8 km/h 以下计时），夜间 23~04 点加收 20%），画面为 C1 样式，保诺的贝壳随方向盘角度(steeringAngleDeg) 1:1 转动，此画面不绘制胡萝卜方向盘图标。按实际距离和时间计费：副驾驶乘客检测(CAN 0x500 bus0 bit2~3) 停车时亮 5 秒 = 乘客上车，起步后从起步价开始计费；熄灭 5 秒 = 付款画面（最后一次停车开始时的金额）。无乘客时显示空车与淡化的起步价。仅供显示。改为 0 再改回 1 即重置计价器（费用、距离、时间归零，从起步价开始）。防冲突：选 0 或 1 时 ClusterHud 自动关闭(0)；打开 ClusterHud(1) 时本项恢复为 -1。只运行一个 HUD 程序。0↔1 切换无需重启 HUD，约 1 秒内生效。未经实车验证。

## 出租车计价器季节背景（试验） (`K9MeterSeason`)

选项：0 自动（按月份） / 1 春 / 2 夏 / 3 秋 / 4 冬（2026-10-24 前的选项名）

仅在“外部 HUD 画面选择”为 1（出租车计价器画面）时使用的附加选项，选择计价器背景的季节。0：自动（默认），随月份变化（3~5月春，6~8月夏，9~11月秋，12~2月冬）。1：春。2：夏。3：秋。4：冬。白天(05点)·黄昏(16点)·夜晚(19点)切换在任何值下都按时间照常进行。其他值（超出范围）按 0 处理。HUD 只读取此值，约 1 秒内生效。与计费无关。未经实车验证。
